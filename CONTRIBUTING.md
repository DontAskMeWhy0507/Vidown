# Contributing to Vidown

Thank you for your interest in contributing to Vidown.

## Current Architecture & Build Pipeline

All extension runtime scripts (`content-script.js`, `background.js`, `common.js`, and `inject/*`) are compiled from structured, readable sources under `src/` via the unified `npm run build` pipeline:

1. **Modular Content Script (`src/content/`)**:
   - The shipped bundle `content-script.js` is generated by `scripts/build_content_script.js`.
   - It compiles 649 structured modules across 776 slots (127 null holes) mapped via `src/content/module-registry.js` and `src/content/slots.js`.
   - Third-party libraries are isolated under `src/content/vendor/` (`cryptojs`, `qrcode`, `stream`, `fast-xml-parser`, `mustache`, `eventemitter3`, `buffer`, `shims`, `parser`, `elliptic`).
   - Project logic is organized semantically into `core/`, `detector/`, `platform/`, `providers/`, and `widget/`.

2. **Modular Background Service Worker (`src/background/`)**:
   - The shipped bundle `background.js` is generated by `scripts/build_background.js`.
   - Decomposed into subsystem modules: `entry/`, `messaging/`, `downloads/`, `storage/`, `tabs/`, `events/`, `crypto/`, `utilities/`.

3. **Modular Common Runtime (`src/common/`)**:
   - The shipped bundle `common.js` is generated by `scripts/build_common.js`.
   - Decomposed into `core-utils/`, `entry/`, `crypto/`, and `utilities/`.

4. **Main-World Inject Extractors (`src/inject/` & `inject/`)**:
   - Source main-world site extractors are maintained under `src/inject/` and built to `inject/` via `scripts/build_inject.js`.

## Building from Source

The build pipeline compiles all extension artifacts from unpacked source:

```bash
# Clone repository
git clone https://github.com/DontAskMeWhy0507/Vidown.git
cd Vidown

# Install dependencies
npm ci

# Full build: compiles common.js, background.js, content-script.js, inject/, and packages release zip
npm run build

# Development build with unminified output and per-module inline V3 sourcemaps
npm run build:dev

# Synchronize module hashes and census metadata
npm run sync:integrity
```

## Developer Debugging with Chrome DevTools (`npm run build:dev`)

Vidown provides full per-module V3 sourcemap support in development mode:

1. Build in development mode:
   ```bash
   npm run build:dev
   ```
2. Open Chrome DevTools (`F12`), navigate to the **Sources** tab.
3. Individual modules are mapped directly to their source paths:
   - `src/content/**`
   - `src/background/**`
   - `src/common/**`
4. Set breakpoints, step through code, and inspect unminified variables directly in the module source files.
5. Packaging the extension (`npm run build` or `npm run package`) automatically detects dev sourcemaps and rebuilds clean production bundles first, guaranteeing no sourcemap comments or bloat contaminate `dist/savior-extension-v3.1.0.zip`.

## Native Companion Setup (Windows / macOS / Linux)

Vidown integrates with a native messaging companion for accelerated FFmpeg downloading and HLS/DASH muxing.

- **Windows**: Run `native\install.bat`. It automatically detects or compiles `host.cs` into `host.exe` using `csc.exe` and registers the host manifest in `%LOCALAPPDATA%\SaviorHelper\com.savior.helper.json` without modifying repository files. To remove, run `native\uninstall.bat`.
- **macOS**: Run `./native/install.sh`. The installer detects `Darwin` and configures manifests in Chrome, Chromium, Brave, and Edge Application Support directories. To remove, run `./native/uninstall.sh`.
- **Linux**: Run `./native/install.sh`. The installer detects `Linux` and installs manifests to `~/.config/google-chrome/NativeMessagingHosts` and `~/.config/chromium/NativeMessagingHosts`. To remove, run `./native/uninstall.sh`.

## Testing & Quality Gates

All contributions must pass all 92 automated test suites:

```bash
# Run all automated test suites
npm test

# Run debuggability and release hygiene tests
node tests/test_debuggability_and_release_hygiene.js

# Run golden characterization tests on real DOM fixtures
node tests/test_golden_behavior.js

# Run background and common messaging oracle test
node tests/test_background_common_messaging.js

# Run crypto test vector verification
node tests/test_crypto_consolidation.js

# Run release package cleanliness test
node tests/test_package_release_cleanliness.js
```

### Constraints & Invariants
- **Release Package Cleanliness**: Release zip `dist/savior-extension-v3.1.0.zip` must remain $\le 15\text{ MB}$ (currently ~1.12 MB) with 0 executables, 0 log files, 0 `node_modules`, no dev sourcemaps, and no dead root files. Entries are sorted lexicographically with deterministic timestamps.
- **Target Platform**: Chrome Manifest V3 (`minimum_chrome_version: 116`).
- **Open Source Release**: Open-source release under the MIT License v3.1.0.
